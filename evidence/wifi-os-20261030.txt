iPadOS 17.7.11 uses the AP6398S as its Wi-Fi interface en0 on the RK3588 EVB10 V10: IOKit goes quiet, the userland's own DHCP client gets a lease,
DNS and TCP carry traffic, no panic (package/Evb10Wifi with WifiNet.cpp, evb10-wifi=5).
Command:  cd uefi-evb10 && EXTRA_KERNEL_ARGS="evb10-wifi=5" CAPTURE_SECS=200 EARLY_STOP=0 tools/xnu-probe/run-kernel.sh wifi19
Revision: 7552f86 (kernel and payload built from that tree; only comments of Evb10Wifi.cpp and nw_abi.h were edited after the build)
Date:     2026-10-30 20:30 (UTC+8); the second section is run wifi17 (a 240 s run of the same level with an earlier transmit queue)
Kernel arguments: the committed defaults of board.toml plus evb10-wifi=5. The network and its passphrase come from .cache/firmware/join.txt (local,
git-ignored, embedded by scripts/build-wifi-firmware.py); the passphrase is not in this file. Names, the last three bytes of every MAC address and
the private network addresses are removed.
What this shows, in order: the firmware's join takes 2.2 s (the same sequence as evb10-wifi=4); the interface en0 is registered; IOKit is quiet 26 s
into the boot log (it was not quiet before the software AES was added; see docs/network.md); the userland's DHCP client then sends and receives
DHCP and en0 has its address (the 83 s status block is the first with DHCP packets: 0 at 73 s); DNS and 36 outgoing TCP connections follow.
Nothing here drives the network from the kernel: the DHCP, DNS and TCP packets are the userland's. Nobody looked at the screen or Settings.
wifi19 is a quiet run (0.13 MB of TCP payload); wifi17 shows the case with a download. Hardware observation; host-side checks are in the commit message.
