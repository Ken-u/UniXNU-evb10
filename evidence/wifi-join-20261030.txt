The AP6398S joins a WPA2-PSK access point with the firmware's supplicant, gets an address by DHCP and answers pings, all driven by the kernel
(package/Evb10Wifi, evb10-wifi=4 with its built-in self-test) on the RK3588 EVB10 V10.
Command:  cd uefi-evb10 && EXTRA_KERNEL_ARGS="evb10-wifi=4" CAPTURE_SECS=100 EARLY_STOP=0 tools/xnu-probe/run-kernel.sh wifi9b
Revision: UniXNU-evb10 1efa0fc plus the station layer as it was when this ran (the code is committed as 7552f86; the run is from an earlier state of it)
Date:     2026-10-30 18:50 (UTC+8)
Kernel arguments: the committed defaults of board.toml plus evb10-wifi=4. The network and its passphrase come from .cache/firmware/join.txt (local, git-ignored),
embedded by scripts/build-wifi-firmware.py; the passphrase is not in this file.
What this shows, in order: the chip is put in infrastructure mode (WLC_SET_INFRA; before that a join only made an ad-hoc network with a random BSSID, which looked
like a link-up event but never produced a key exchange), the join command gives AUTH, LINK up, ASSOC, then PSK_SUP "keyed" (status 6) from the firmware's 4-way
handshake; the self-test then sends DHCP DISCOVER/REQUEST, ARP and ICMP echo built in the driver through the same transmit path nw_wifi_tx uses. The access
point answered all of it: lease, router MAC, four of four pings. Names, the leading three bytes kept, the last three bytes of addresses and the private address
are removed. This is a first on-air result of one run in one place (signal -81 dBm on 2.4 GHz), not a throughput or stability measurement.
